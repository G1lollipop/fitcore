## 原始Streamlit实现

### 工作原理

1. **单文件应用**：`app_qa.py` 包含了所有的前端UI和后端逻辑
2. **直接调用**：在同一个Python进程中直接实例化和调用 `RagService`
3. **同步执行**：用户输入后，直接调用 `rag.chain.invoke()` 获取响应
4. **流式输出**：使用 `write_stream()` 实时显示AI的回复

### 核心代码

```python
# 创建RAG服务实例
if "rag" not in st.session_state:
    st.session_state["rag"] = RagService()

# 处理用户输入
if prompt:
    # 构建会话配置
    session_config = {
        "configurable": {
            "session_id": st.session_state["session_id"]
        }
    }
    
    # 直接调用RAG服务
    res_stream = st.session_state["rag"].chain.stream({"input":prompt}, session_config)
    
    # 显示流式回复
    st.chat_message("assistant").write_stream(capture(res_stream, ai_res_list))
```

### 优缺点

**优点**：
- 实现简单，代码量少
- 部署方便，只需一个文件
- 无需处理跨语言通信

**缺点**：
- UI定制能力有限
- 性能受限于Python单线程
- 无法充分利用前端框架的优势

## 新Next.js前端实现

### 工作原理

1. **组件化设计**：使用React组件构建UI界面
2. **状态管理**：使用 `useState` 管理聊天消息和输入状态
3. **API调用**：使用 `fetch` API发送HTTP请求到后端服务
4. **错误处理**：实现了完善的错误捕获和处理机制

### 核心代码

```typescript
// 处理发送消息
const handleSendMessage = async () => {
  if (!inputValue.trim()) return

  // 添加用户消息到界面
  const newMessage: Message = {
    role: 'user',
    content: inputValue
  }
  setMessages(prev => [...prev, newMessage])
  setInputValue('')
  setIsLoading(true)

  try {
    // 调用后端API
    const response = await fetch('http://localhost:8000/api/chat', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        message: inputValue,
        sessionId: Math.random().toString(36).substr(2, 9)
      })
    })

    // 处理响应
    if (!response.ok) {
      throw new Error('API response failed')
    }

    const data = await response.json()
    const aiResponse: Message = {
      role: 'assistant',
      content: data.response
    }
    setMessages(prev => [...prev, aiResponse])
  } catch (error) {
    // 错误处理
    console.error('Error sending message:', error)
    const errorResponse: Message = {
      role: 'assistant',
      content: 'I apologize, but I\'m having trouble processing your request right now. Please try again later.'
    }
    setMessages(prev => [...prev, errorResponse])
  } finally {
    setIsLoading(false)
  }
}
```

### 优缺点

**优点**：
- 现代化的UI设计，响应速度快
- 组件化开发，代码结构清晰
- 更好的用户体验，支持实时状态更新
- 可以利用前端生态系统的丰富资源

**缺点**：
- 需要额外的后端API服务
- 增加了系统复杂度
- 需要处理跨域和网络错误

## 后端API服务实现

### 工作原理

1. **FastAPI框架**：使用FastAPI创建高性能的HTTP服务
2. **RAG服务集成**：在服务启动时实例化 `RagService`
3. **API端点**：暴露 `/api/chat` 端点接收前端请求
4. **会话管理**：使用 `sessionId` 维护会话状态

### 核心代码

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
from rag import RagService
import uvicorn

app = FastAPI()

# 配置CORS
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

rag_service = None

class ChatRequest(BaseModel):
    message: str
    sessionId: str

class ChatResponse(BaseModel):
    response: str

def get_rag_service():
    global rag_service
    if rag_service is None:
        rag_service = RagService()
    return rag_service

@app.post("/api/chat", response_model=ChatResponse)
async def chat(request: ChatRequest):
    try:
        rag = get_rag_service()
        session_config = {
            "configurable": {
                "session_id": request.sessionId
            }
        }
        
        # 调用RAG服务
        response = rag.chain.invoke({"input": request.message}, session_config)
        
        return ChatResponse(response=response)
    except Exception as e:
        print(f"Error in chat API: {e}")
        return ChatResponse(response=f"Error: {str(e)}")

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

## API调用流程

### 完整调用链路

1. **用户输入**：在前端输入框中输入问题
2. **前端处理**：
   - 创建用户消息对象
   - 更新UI显示用户消息
   - 发送HTTP POST请求到后端API
   - 显示加载状态
3. **后端处理**：
   - 接收请求并解析JSON数据
   - 获取RAG服务实例
   - 构建会话配置
   - 调用 `rag.chain.invoke()` 获取AI回复
   - 返回JSON格式的响应
4. **前端处理响应**：
   - 解析JSON响应
   - 创建AI消息对象
   - 更新UI显示AI回复
   - 隐藏加载状态
5. **错误处理**：
   - 捕获网络错误和API错误
   - 显示友好的错误提示

### 数据流向

```
用户输入 → 前端 → HTTP请求 → 后端API → RAG服务 → 大模型 → RAG服务 → 后端API → HTTP响应 → 前端 → UI显示
```

## 故障排除

### 常见错误及解决方案

1. **ModuleNotFoundError: No module named 'langchain_classic'**
   - **原因**：未激活虚拟环境或依赖未安装
   - **解决方案**：激活虚拟环境并安装依赖

2. **API调用失败，返回404或500错误**
   - **原因**：后端API服务未运行或出现错误
   - **解决方案**：检查后端服务状态，查看终端日志

3. **前端无法连接到后端**
   - **原因**：跨域问题或网络配置错误
   - **解决方案**：确保CORS配置正确，检查防火墙设置

4. **虚拟环境激活失败**
   - **原因**：路径错误或权限问题
   - **解决方案**：检查虚拟环境路径，确保有执行权限
