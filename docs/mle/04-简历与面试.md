## 2. 简历 Bullet（分档，挑 3–5 条最强的用）

### A. 现在就能写（真实数字，立刻可用）⭐

1. **Built an offline retrieval evaluation harness** (document-level qrels, graded nDCG@k / Recall@k / MRR / abstention) for a hybrid RAG pipeline; used it to **data-drive the dense/sparse fusion weight**, discovering that equal-weight fusion (nDCG@10 0.82) underperformed pure vector (0.99) and that 0.8 vector-weight was optimal for same-language retrieval — shipped at **nDCG@10 0.92, MRR 0.91**.

2. **Designed a hybrid retriever** (Gemini embeddings + BM25, weighted RRF fusion) over Chroma / Supabase pgvector (HNSW), with an optional CrossEncoder reranker that **gracefully degrades** when GPU deps are absent (covered by dual-mode tests).

3. **Set up CI regression gates for ML quality**: per-PR retrieval eval against frozen metric floors + nightly LLM-as-judge answer eval (relevance/completeness/accuracy) that auto-files regression issues — preventing silent retrieval degradation.

4. **Engineered an ingestion pipeline** with MD5 dedup, source-level replace, reference-section trimming, and embedding rate-limit backoff (Gemini free-tier 100/min, 1000/day), reliably ingesting long academic PDFs; enforced **CC-BY-only data licensing** governance via a source registry.

5. **Built a 2-step tool-calling agent** (plan → parallel tools → streamed generation) where the LLM selects retrieval depth (k∈{3,5,8}); decoupled **retrieval (Python) from generation (Next.js)** for independent eval and scaling; SSE streaming with per-turn observability (tools used, latency, mode).

## 3. 项目描述段落（放在简历项目区 / LinkedIn / 个人网站）

> **FitCore** is an AI fitness coach built as a monorepo: a Next.js app orchestrating a tool-calling LLM agent, and a standalone FastAPI RAG service. The retrieval layer combines Gemini embeddings with BM25 via weighted fusion over Supabase pgvector, with an optional CrossEncoder reranker. What sets it apart is the **evaluation discipline**: a document-level offline retrieval harness (Recall@k, graded nDCG, MRR, abstention) and an LLM-as-judge answer evaluator, both wired into CI as regression gates. I used the harness to make a data-driven fusion-weight decision (shipped nDCG@10 ≈ 0.92) — turning "I built a RAG demo" into "I make metrics-driven retrieval-engineering decisions."

## 4. 面试故事库（STAR，每个都带决策与数字）

### 故事 1（王牌）：用评估驱动检索决策

- **S（情境）**：FitCore 的 RAG 检索用了向量 + BM25 混合，但融合权重一开始是拍脑袋的 0.5/0.5，不知道好不好。
- **T（任务）**：客观地决定融合权重，而不是凭感觉。
- **A（行动）**：我搭了一套离线检索评估——文档级 qrels、分级 nDCG、Recall@k、MRR，还做了权重网格扫描（`--sweep`）。发现①跨语言场景下 BM25 词法匹配几乎失效（nDCG 0.28），等权融合（0.82）反而被 BM25 拖累，劣于纯向量（0.99）；②同语言英文场景下 0.8 向量权重的融合最优（0.986），且优于纯向量——这正是 hybrid 检索该有的样子。
- **R（结果）**：把生产权重定为 0.8，nDCG@10 ≈ 0.92、MRR ≈ 0.91，并把评估接进 CI 做回归门禁，防止后续改动悄悄退化。
- **可追问的深挖点**：为什么 BM25 跨语言失效（词法 vs 语义）；RRF 怎么融合；为什么用 nDCG 而非 recall（recall 在小 KB 饱和了）；qrels 为什么用 source 级（抗 re-chunk）。

### 故事 2：生产级的优雅降级

- **S**：CrossEncoder 重排需要 `torch`，但云端免费实例内存装不下。
- **T**：本地能用重排做实验，云端不能因为缺依赖就崩。
- **A**：把重排做成可选 + 懒加载，ImportError 时自动降级到基础融合，并写了 dual-mode 测试覆盖所有降级路径 + sticky 缓存标志。
- **R**：同一份代码本地可跑重排实验、云端稳定运行，零崩溃。
- **深挖点**：bi-encoder vs cross-encoder 的精度/速度权衡；什么时候值得上重排。

### 故事 3（做完 Track D 后）：蒸馏降本提速

- **S**：自然语言记录每次都调 Gemini，慢且贵。
- **T**：在不掉准确率的前提下降延迟、降成本。
- **A**：用 Gemini 当 teacher 造数据，LoRA 微调一个 1.5B 小模型当 student，做知识蒸馏；在 held-out 集上对比字段抽取 F1 / 数值 MAE / 延迟 / 成本。
- **R**：student 在抽取 F1 上追平 teacher，p95 延迟降 5x，自托管后单次成本归零。
- **深挖点**：LoRA 原理、怎么造蒸馏数据、怎么防过拟合、怎么 serve（量化/vllm）。

### 故事 4：数据治理 / 工程素养

- **S**：RAG 知识库要喂权威健身科学资料，但很多源有版权。
- **T**：构建合法、干净、可复现的知识库。
- **A**：建 `sources.yaml` 源登记表，只收 CC-BY/公共领域/官方指南，写抓取管线（trafilatura + UA 回退 + PDF 解析 + 自动裁参考文献降噪），灌库做 MD5 去重 + 限流退避。
- **R**：可复现、合规、低噪声的知识库管线。
- **深挖点**：chunking 怎么选、embedding 限流怎么处理、去重为什么用 MD5。

## 5. 常见追问与应答要点

| 面试官可能问 | 你要答出的核心 |
|---|---|
| "你的 RAG 怎么评估的？" | 检索层（Recall/nDCG/MRR + abstention，文档级 qrels）+ 生成层（LLM-judge）+ CI 门禁。**全链路**。 |
| "recall 1.0 是不是太完美了？" | **主动承认**：KB 只有 16 文档，recall 饱和；所以头条用 nDCG/MRR；下一步扩库提升区分度。 |
| "为什么用 hybrid 而不是纯向量？" | 同语言下词法+语义互补，0.8 融合(0.986) > 纯向量(0.955)；但跨语言时 BM25 失效，要切纯向量——**场景化决策**。 |
| "你自己训过模型吗？" | （做完 Track D）讲蒸馏微调 1.5B parser；（没做前）诚实说目前是评估+检索为主，正在做蒸馏。 |
| "怎么防止幻觉？" | prompt 强制接地 + 资料不足弃答 + （Track A）faithfulness 评估量化。 |
| "上生产你会怎么监控？" | （Track B）latency 分解、token 成本、检索命中分数、数据漂移告警。 |
